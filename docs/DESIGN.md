# TweetSift Technical Design

This document describes the current public architecture of TweetSift.

## Product Scope

TweetSift is a Chrome Manifest V3 extension that helps users classify and save Twitter/X posts into dated bookmark folders.

Core workflows:

- Save the current post to a folder with a shortcut.
- Show a recommendation for Video, Nano, or Image posts.
- Create today's folder on demand.
- Remove the current post from bookmarks.
- Export selected bookmark folders to JSON.

## Keyboard Mapping

Shortcut keys are user-facing controls. Internal category IDs are separate.

| Key | Action | Category ID |
| --- | --- | --- |
| `` ` `` | Use recommendation | From classifier |
| `1` | Nano | `2` |
| `2` | Video | `1` |
| `3` | Image | `3` |
| `z` | Remove current post from bookmarks | n/a |

Shortcuts are ignored while an input, textarea, contenteditable element, or textbox is focused.

## Folder Rules

TweetSift creates one folder per category per local day:

- `yyMMdd-Video`
- `yyMMdd-Nano`
- `yyMMdd-Image`

Folder names are generated by `src/background/folders.js`. All daily cache keys use the browser's local date.

## Bookmark Flow

```text
keydown in content script
  -> extract current post from viewport
  -> ask background for enabled state, dedup state, hashes, and folder cache
  -> find or create today's target folder when needed
  -> click the native X bookmark button so the post enters the bookmark pool
  -> call bookmarkTweetToFolder to put it in the target folder
  -> store local record and update local counters
  -> mark the post and show a toast
```

The native bookmark click keeps TweetSift closer to X's own bookmark state. The folder API call then handles the folder assignment.

## Remove Flow

`z` acts on the current post only. It is not an operation-history undo stack.

```text
z key
  -> detect whether current post is bookmarked
  -> click the native X bookmark button to remove the bookmark
  -> optionally call RemoveTweetFromBookmarkFolder when folder data is available
  -> remove local record and decrement local counters
  -> clear local UI marker
```

Folder removal is best effort. Native unbookmarking is the main source of truth.

## Export Flow

The popup asks the background service worker to coordinate export work. The background relays requests to a Twitter/X tab where the content script can call the same-origin X web endpoints.

```text
popup
  -> request folder list
  -> user selects folders
  -> background starts export job
  -> content script fetches BookmarkFolderTimeline pages
  -> content script parses tweet fields
  -> content script optionally repairs missing authors with publish.twitter.com/oembed
  -> popup downloads JSON results
```

Exports are intentionally downloaded by the browser instead of uploaded anywhere.

## Local Storage

TweetSift uses `chrome.storage.local` for browser-local state.

```json
{
  "enabled": true,
  "folders": {
    "date": "2026-06-21",
    "video": { "id": "...", "name": "260621-Video" },
    "nano": { "id": "...", "name": "260621-Nano" },
    "image": { "id": "...", "name": "260621-Image" }
  },
  "bookmarked": {
    "date": "2026-06-21",
    "tweets": {
      "tweet_id": {
        "category": 2,
        "folderId": "...",
        "time": 1780000000000
      }
    }
  },
  "stats": {
    "date": "2026-06-21",
    "today": { "video": 3, "nano": 2, "image": 5 },
    "total": 128
  },
  "queryHashes": {
    "bookmarkTweetToFolder": "...",
    "createBookmarkFolder": "...",
    "BookmarkFoldersSlice": "...",
    "BookmarkFolderTimeline": "...",
    "CreateBookmark": "...",
    "DeleteBookmark": "...",
    "RemoveTweetFromBookmarkFolder": "..."
  }
}
```

The `bookmarked`, `folders`, and `stats` stores are normalized by local date. Re-enabling the extension after disabling it clears the session caches.

## Permissions

The manifest keeps permissions narrow:

- `storage` for local state.
- `webRequest` for observing X GraphQL operation hashes.
- `x.com` and `twitter.com` host permissions for the content script and bookmark/folder actions.
- `publish.twitter.com` host permission for the public oEmbed author lookup used during JSON export.

The extension no longer uses `chrome.cookies`.

## Known Risks

- X can change web endpoint names, hashes, payload shapes, or DOM structure.
- Folder actions depend on account-level Bookmark Folders access.
- Exported JSON may contain user-private bookmark context, so sample exports are not committed.
- Local counters are best-effort extension activity counters, not X server-side stats.

## Verification Checklist

- Build succeeds with `npm run build`.
- `dist/manifest.json` contains the current `package.json` version.
- Loading `dist/` in Chrome succeeds without permission surprises.
- On X, `1`, `2`, `3`, and `` ` `` save to the expected folders.
- `z` removes the current bookmarked post.
- Popup hash status, folder loading, and JSON export work on a logged-in account with Bookmark Folders access.
